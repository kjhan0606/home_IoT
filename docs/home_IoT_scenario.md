# 0. 이 문서에 대하여

이 문서는 지금까지 만든 홈 IoT 앱과 서버가 어디까지 왔는지, 앞으로 어떤 순서로 만들지, 돈은 어떻게 벌 수 있을지를 한 곳에 모아 쉬운 말로 정리한 것입니다. 개발 용어는 꼭 필요한 곳에만 쓰고 그때마다 뜻을 풀어 두었습니다. 가격과 수치는 모두 초안이며 바뀔 수 있습니다.

참고한 자료는 다음과 같습니다.

- 앱과 허브 코드 저장소의 설명 문서들 (README, CLAUDE.md, 앱 설명서, 앱 연결 방식 문서)
- 프리미엄 서버 설계 초안 문서
- 수익 모델 엑셀 파일 (home_IoT_revenue_model.xlsx)

# 1. 한눈에 보기

## 1-1. 목표

집에 있는 삼성, LG, 로보락 같은 여러 회사의 가전을 앱 하나로 살펴보고 조작하는 것이 목표입니다. 앱은 회사 이름에 따라 화면을 따로 만들지 않고, 기기가 "전원", "볼륨", "청소 시작" 같은 공통 기능을 가졌는지만 보고 화면을 그립니다. 그래서 새 회사의 기기를 붙여도 앱 화면은 고칠 필요가 없습니다.

## 1-2. 전체 그림은 세 겹입니다

1. **기본 (서버 없음)**. 폰 앱이 삼성 SmartThings와 LG ThinQ의 클라우드에 직접 연결합니다. 우리가 운영하는 서버가 없으므로 비용이 들지 않고, 이 기본 기능은 계속 무료로 둡니다.
2. **선택 (집 허브)**. 집 안에 항상 켜 둔 작은 컴퓨터에 허브 프로그램을 돌립니다. 삼성 TV를 집 안 통신으로 직접 제어하거나 로보락 청소기의 지도를 보고 싶을 때 씁니다. 직접 설치해서 쓰는 방식이라 우리 쪽 서버 비용은 없습니다.
3. **선택 (유료 프리미엄 서버)**. 우리가 운영하는 서버입니다. 알림, 토큰 자동 갱신, 집 밖 원격 제어 같은 "있으면 편한 기능"을 월 구독으로 제공합니다. 아직 설계 초안만 있고 만들지는 않았습니다.

아래 그림에서 화살표는 "누가 누구에게 말을 거는가"를 뜻합니다. 점선 부분(3번)은 아직 만들지 않은 부분입니다.

# 2. 현재 상태

## 2-1. 이미 만들어져 GitHub의 main에 합쳐진 것

용어를 먼저 풀어 두면 GitHub는 코드를 인터넷에 보관하는 서비스이고, main은 "공식 본선"에 해당하는 갈래입니다. PR은 "이 작업을 본선에 합쳐 주세요"라는 요청입니다. 세 건이 이미 합쳐졌습니다.

| 번호 | 내용 | 쉬운 설명 |
|---|---|---|
| PR #1 | SmartThings와 LG ThinQ 허브 어댑터 | 허브가 삼성과 LG 가전(세탁기, 건조기, 냉장고, 로봇청소기, 삼성 TV)을 클라우드로 읽고 제어하게 하는 부분 |
| PR #2 | Roborock 어댑터 | 로보락 청소기를 집 안 통신으로 우선 제어하고, 안 되면 로보락 클라우드로 대신하는 부분. 방별 청소, 구역 청소, 지도 포함 |
| PR #3 | Flutter 앱 | 허브에 연결해서 쓰는 폰 앱. 한국어 화면, 기기 목록과 상세, 청소기 지도 화면 |

## 2-2. 내 컴퓨터에만 있고 아직 GitHub에 올리지 않은 것

작업 갈래를 "브랜치"라고 부릅니다. 아래 두 갈래는 이 컴퓨터에만 있고 GitHub에는 올라가 있지 않습니다. 즉 컴퓨터가 고장 나면 사라질 수 있으니 올릴지 여부를 정해야 합니다(8장 참고).

| 작업 갈래 | 내용 |
|---|---|
| feature/direct-cloud | 앱이 서버 없이 삼성과 LG에 직접 연결하는 방식을 추가한 작업. 연결 방식을 갈아 끼우는 구조, 처음 실행 시 안내 화면, 토큰 보관, 설정 화면이 들어 있음. 본선 대비 커밋 3개 |
| docs/premium-server | 프리미엄 서버 설계 초안 문서(premium-server.md) 한 편. 별도 폴더(home_IoT_premium)에 있음 |

| 대상 | 자동 시험 수 | 비고 |

## 2-4. 아직 확인하지 못한 것

- 진짜 삼성, LG 계정 토큰과 진짜 가전으로는 한 번도 시험하지 않았습니다. 자동 시험은 모두 가짜 응답을 썼습니다.
- iPhone에서 실행해 본 적이 없습니다. 지금 쓰는 리눅스 컴퓨터로는 iPhone용 앱을 만들 수 없습니다. 웹 화면으로만 확인했습니다.
- 안드로이드용 앱도 아직 만들어 보지 못했습니다.
- 일부 기기 명령의 세부 값은 추정입니다. 실제 기기에서 확인이 필요합니다.
- 집 안 통신으로 삼성 TV를 제어하는 기능은 예전 집 네트워크에서 확인했습니다. 지금 네트워크에서는 다시 확인해야 합니다.

# 3. 앱 시나리오

## 3-1. 연결 방식 세 가지

| 방식 | 서버 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|---|
| 직접 연결 (새로 설치하면 기본) | 없음 | 삼성과 LG의 세탁기, 건조기, 냉장고, 로봇청소기 제어. 삼성 SmartThings 기기 전반. 두 회사 기기를 한 목록에 표시 | 삼성 TV 집 안 직접 제어, 로보락, 청소기 지도, 실시간 알림 (1분마다 새로 확인) |
| 허브 | 집 안 컴퓨터 | 위 기능에 더해 삼성 TV 집 안 직접 제어, 로보락, 청소기 지도와 방별 청소, 실시간 반영 | 집 밖에서 사용(같은 Wi-Fi 필요) |
| 릴레이 (앞으로, 유료) | 우리 서버 | 알림, 로보락, 로그인 방식의 SmartThings 연결, 집 밖 사용 | 아직 만들지 않음. 연결 자리만 준비됨 |

이미 허브를 기억하고 있는 앱은 계속 허브 방식으로 시작합니다. 새로 설치한 앱은 직접 연결로 시작합니다. 방식은 설정 화면의 "연결 방식"에서 바꿉니다.

LG ThinQ의 공식 연결에는 TV가 없기 때문에, 직접 연결 방식에서는 LG TV를 다룰 수 없습니다.

## 3-2. 처음 사용하는 순서

1. 앱을 처음 열면 안내 화면이 나오고 연결 방식을 고릅니다. 기본은 직접 연결입니다.
2. 직접 연결을 고르면 SmartThings 토큰을 붙여 넣습니다. 발급 주소는 account.smartthings.com/tokens 입니다.
3. LG 가전도 있으면 LG 토큰과 국가(한국이면 KR)를 입력합니다. 발급 주소는 connect-pat.lgthinq.com 입니다. 국가는 LG 계정의 국가와 같아야 합니다.
4. 기기 목록이 나타납니다. 앱을 켜 두는 동안 1분마다 자동으로 새로 읽어 옵니다.
5. 허브 방식을 고르면 같은 Wi-Fi의 허브를 자동으로 찾습니다. 못 찾으면 허브 주소를 직접 입력합니다.
6. iPhone은 처음 실행할 때 "로컬 네트워크" 접근을 허용해야 합니다. 허브 방식에서 필요한 설정입니다.

## 3-3. 토큰은 어디에 보관하나

- 토큰은 폰의 보안 보관함(iPhone은 키체인, 안드로이드는 키스토어)에만 저장합니다. 일반 설정 파일에는 저장하지 않고, 삼성과 LG 자신의 주소 외에는 어디로도 보내지 않습니다.
- **SmartThings 개인 토큰은 24시간이 지나면 만료됩니다.** 그래서 매일 새로 발급해 붙여 넣어야 하는 불편이 있습니다. 앱은 토큰이 오래되면 미리 알려 주고, 만료되어 거절당하면 화면 위에 안내 띠를 띄워 토큰 입력 화면으로 바로 갈 수 있게 합니다.
- 이 불편을 없애려면 "SmartThings 로그인 연결(OAuth)" 방식이 필요한데, 이는 비밀 열쇠를 안전하게 보관할 작은 서버가 있어야 합니다. 그래서 프리미엄 서버의 첫 번째 기능으로 잡았습니다.
- 한쪽 회사 연결이 끊겨도 다른 회사의 기기는 계속 보입니다.

## 3-4. 주요 화면

- 안내 화면(연결 방식과 토큰 입력)
- 기기 목록. 종류별 또는 방별로 묶어 보여 주고, 켜짐 표시와 전원 버튼이 있으며 당겨서 새로고침
- 기기 상세. 기기가 가진 기능에 맞춰 자동으로 구성됩니다.
  - TV는 전원, 볼륨, 채널, 입력, 재생, 앱
  - 세탁기와 건조기는 상태, 남은 시간, 시작과 일시정지와 정지. 기기에서 "원격 시작"을 켜지 않았으면 한국어로 안내하고 명령을 보내지 않음
  - 냉장고는 현재 온도, 설정 온도 조절, 문 열림, 급속 냉각과 냉동
  - 로봇청소기는 상태, 배터리, 시작과 정지와 충전대 복귀, 흡입력, 물걸레, 소모품, 방 선택
  - 밝기, 색, 잠금, 센서 등과 알 수 없는 기능을 위한 기본 카드
- 청소기 지도(허브 방식 전용). 방을 눌러 청소, 구역을 그려 청소, 길게 눌러 그 위치로 이동
- 설정. 연결 방식, 클라우드 계정(토큰 입력과 삭제), 허브 주소, 로보락 계정 연결과 해제
- 한국어 화면이며 시스템의 밝은 모드와 어두운 모드를 따라갑니다.

# 4. 서버 시나리오

## 4-1. 허브와 프리미엄 서버는 무엇이 다른가

| 항목 | 집 허브 (선택, 직접 운영) | 프리미엄 서버 (선택, 유료) |
|---|---|---|
| 운영 주체 | 사용자 본인 | 우리 |
| 위치 | 사용자의 집 안 컴퓨터 | 인터넷의 서버(서울 지역 권장) |
| 사용자 수 | 한 집 | 여러 사용자 |
| 로그인 | 집 안에서만 쓰므로 공유 비밀번호 정도 | 계정 로그인 필수 |
| 강점 | 삼성 TV 집 안 제어, 로보락 지도, 인터넷 없이도 동작 | 알림, 토큰 자동 갱신, 집 밖 원격 제어, 가족 공유 |
| 비용 | 우리 쪽 서버 비용 없음 | 서버, 알림, 보안, 결제 수수료 등 |

허브는 앞으로도 무료로 계속 쓸 수 있게 둘지가 열린 질문입니다(8장).

## 4-2. 프리미엄 서버 설계 초안의 핵심

**기술.** 서버는 파이썬 FastAPI와 PostgreSQL 데이터베이스로 작게 시작합니다. 지금 허브에 있는 삼성, LG, 로보락 연결 코드를 최대한 다시 씁니다. 처음부터 복잡한 구조를 쓰지 않고 서버 한 덩어리와 데이터베이스 하나로 시작합니다. 앱에는 세 번째 연결 방식 하나만 추가하면 되고 화면은 그대로입니다.

**로그인.** 이메일과 비밀번호, Google, Facebook, Apple 로그인을 지원합니다. 애플 심사 규칙상 구글이나 페이스북 같은 로그인을 넣으면 개인정보를 덜 받는 동등한 로그인도 함께 제공해야 하므로 Apple 로그인은 넣는 것으로 정했습니다. Facebook은 꼭 필요한지 다시 따져 볼 항목입니다. 앱 안에서 계정을 삭제할 수 있어야 하는 것도 스토어 규칙입니다.

**토큰 암호화 보관.** 사용자의 집 기기를 움직일 수 있는 토큰이 가장 위험한 자산입니다. 그래서 "열쇠를 넣은 금고를 또 다른 금고에 넣는" 이중 암호화를 씁니다. 데이터베이스가 통째로 유출돼도 토큰을 읽을 수 없게 하고, 비밀번호는 원문을 저장하지 않으며, 로그에도 남기지 않습니다.

**관리자 화면.** 사용자, 구독, 사용량, 연결 상태, 환불, 기능 켜고 끄기와 한도 조정, 기록 조회 메뉴를 둡니다. 역할을 나눠(소유자, 고객지원, 결제 담당, 조회 전용) 권한을 제한하고, 관리자 로그인은 2단계 인증을 필수로 합니다. 관리자도 토큰 원문은 볼 수 없습니다.

**알림.** 서버가 기기 상태를 주기적으로 확인하다가 "세탁 중에서 완료로 바뀌는 순간"을 잡아 iPhone과 안드로이드의 알림 서비스로 보냅니다. 확인 횟수가 늘면 SmartThings 사용량과 비용이 늘기 때문에 등급별로 확인 간격을 제한합니다.

**로보락.** 서버가 로보락 클라우드를 대신 호출해 지도와 청소 명령을 중계합니다. 다만 현재 로보락 연결은 공식이 아닌 방식이어서, 돈을 받는 서비스로 제공하면 약관 문제가 생길 수 있습니다. 공식 파트너 경로를 확인하기 전에는 "실험 기능"으로 표시하는 편이 안전합니다.

**홈 에이전트(선택).** 클라우드 서버는 집 안 기기에 직접 닿을 수 없습니다. 그래서 집 안에 아주 가벼운 프로그램을 두고 집에서 서버로 먼저 연결하게 합니다. 공유기의 문을 열 필요가 없어 안전합니다. 클라우드 기기만 쓰는 사용자는 이 프로그램 없이도 대부분의 기능을 씁니다.

**결제.** 앱 안에서 파는 구독은 애플과 구글의 결제를 씁니다. 서버는 앱이 알려 준 내용을 그대로 믿지 않고 스토어에 직접 확인한 뒤 등급을 바꿉니다. 웹 결제는 운영 부담이 커서 처음에는 넣지 않는 것을 권장합니다.

**개인정보.** 이메일과 기기 정보 등 꼭 필요한 것만 받고, 처리방침과 동의 절차를 갖추며, 유출 시 신속 통지 절차를 준비합니다. 법률 자문이 아니므로 출시 전에 전문가 검토를 받는 것이 좋습니다.

# 6. 수익 시나리오

엑셀 파일의 기본 입력값으로 계산한 월 기준 숫자입니다. 세금은 빠져 있는 세전 이익입니다.

## 6-1. 가정

- Pro 유료 사용자 10,000명, Max 유료 사용자 1,000명, Mmax는 0명
- 가격은 부가세 10% 포함이고, 스토어 수수료는 부가세를 뺀 금액에 적용
- AWS(서버) 월 비용은 300만원으로 추정, SmartThings 사용료는 아직 모르므로 0원으로 둠, 결제와 기타 비용도 0원
- 목표는 월 순이익 1,000만원

## 6-2. 계산 과정

| 항목 | 수수료 15% (기본) | 수수료 30% (시나리오) |
|---|---|---|
| 총매출 (부가세 포함) | 2,000만원 | 2,000만원 |
| 부가세 | 약 182만원 | 약 182만원 |
| 부가세 뺀 매출 | 약 1,818만원 | 약 1,818만원 |
| 스토어 수수료 | 약 273만원 | 약 545만원 |
| 순매출 | 약 1,545만원 | 약 1,273만원 |
| AWS 추정 | 300만원 | 300만원 |
| 세전 이익 | **약 1,245만원 (12.45M)** | **약 973만원 (9.73M)** |
| 목표 1,000만원 대비 | 약 245만원 초과 (달성) | 약 27만원 부족 (미달) |

## 6-3. 읽는 법

- 수수료가 15%이면 목표를 넘기지만, 30%이면 살짝 모자랍니다. 애플의 소규모 사업자 프로그램(신청해야 적용)에 가입하는 것이 그만큼 중요합니다.
- **손익분기 API 예산은 약 245만원입니다.** SmartThings 사용료가 월 245만원을 넘으면 목표 이익을 못 채운다는 뜻입니다. 수수료 30%에서는 사용료가 0원이어도 목표에 못 미칩니다.
- 무료 사용자는 전환율 3%를 가정하면 약 35만 5천 명이 필요합니다(유료 11,000명 ÷ 0.03 − 11,000). 전환율이 2%이면 약 53만 9천 명, 5%이면 약 20만 9천 명입니다. 무료 사용자가 이만큼 모이는 것 자체가 큰 도전입니다.
- 수수료 15%일 때 SmartThings 사용료별 세전 이익은 0원이면 1,245만원, 100만원이면 1,145만원, 300만원이면 945만원(미달), 500만원이면 745만원, 800만원이면 445만원입니다.
- Pro 1,000원은 사용자 한 명당 실제로 남는 돈이 대략 640~770원 수준이라 아주 얇습니다. 서버나 API 비용이 조금만 늘어도 적자가 납니다.

## 6-4. 주의할 점

1. AWS 300만원은 추정치입니다. 실제 구조와 사용량에 따라 크게 달라지므로 실제 청구액으로 바꿔야 합니다.
2. SmartThings의 상업용 API 요금을 아직 모릅니다. 삼성이 2026년 10월부터 API를 유료로 바꾼다고 발표했고, 개인 개발자용 월 4.99달러 요금제가 있지만 여러 사용자를 대신해 호출하는 서비스는 상업용 계약 대상일 가능성이 큽니다. 위 표에서 0원으로 둔 값이 가장 불확실한 값입니다.
3. 법인세와 소득세는 빠져 있어서 실제 손에 남는 돈은 이보다 적습니다. 부가세 신고에서의 매입세액 공제도 반영하지 않았습니다.
4. 구글 플레이의 한국 15% 수수료는 2026년 12월 31일까지 적용되는 것으로 가정했고, 이후 규정은 다시 확인해야 합니다.
5. 무료 사용자가 늘어나는 데 따른 서버 비용은 AWS 추정치 안에 이미 들어 있다고 가정했습니다.
6. 등급 구성과 가격은 확정이 아닌 초안입니다.

# 8. 결정이 필요한 사항

1. **SmartThings API 비용을 누가 낼 것인가.** 우리가 낼지, 사용자가 각자 낼지, 상업 계약을 맺을지에 따라 가격표 전체가 흔들립니다. 가장 먼저 삼성에 문의해야 합니다.
2. **로보락을 Max에 넣을 것인가.** 공식 경로가 없으면 빼거나 "실험 기능"으로 표시하는 방법이 있습니다.
3. **Pro 가격을 1,000원으로 둘 것인가.** 남는 돈이 얇으므로 올리거나 연간 결제를 두는 방법도 있습니다. 스토어에 1,000원이라는 가격 단계가 있는지도 확인해야 합니다.
4. **애플 소규모 사업자 프로그램에 신청할 것인가.** 신청하면 수수료가 30%에서 15%로 내려가 위 계산에서 목표 달성 여부가 갈립니다. 권장합니다. 사업자 등록을 개인사업자로 시작할지도 함께 정해야 합니다.
5. **아직 올리지 않은 두 작업(직접 연결, 프리미엄 서버 초안)을 GitHub에 올릴 것인가.** 올려 두면 이 컴퓨터가 고장 나도 안전하고, 다른 컴퓨터나 Mac에서 이어서 작업할 수 있습니다. 다만 올리는 것은 외부에 보이는 작업이라 Juhan님의 승인이 있어야 진행합니다.
6. **허브 방식을 유료 서비스 시작 후에도 계속 무료로 둘 것인가.**
7. **Facebook 로그인이 꼭 필요한가.** 사용자가 적으면 빼고 이메일, Google, Apple만 두는 편이 부담이 적습니다.
8. **홈 에이전트를 Max 출시에 포함할 것인가.** 클라우드 기기 전용으로 먼저 내는 안이 더 단순합니다.
9. **계정 삭제 후 유예 기간과 구독 종료 후 데이터 보관 기간.**
10. **고객지원 약속 수준.** Mmax의 우선 지원 응답 시간을 혼자서 지킬 수 있는지 따져 봐야 합니다.
